# Case 04：双模式创建弹窗与异步竞态

项目空间已有一个「新建项目」弹窗。正常慢速操作基本可用，但快速切换创建方式、连续选择模板，或关掉弹窗后马上重开，都会让过期的模板响应改写当前表单。请修复候选代码，不要重做页面。

## 用户可见契约

- 首次打开、取消或按 Escape 后重新打开，都从「手动创建」开始：名称为空、席位数为 3、没有选中的模板，也没有上次的加载状态、预览或错误。
- 在同一次打开期间，两种模式共用项目名称。切换模式不会丢掉已输入的名称、手动席位数或已选模板；返回模板模式时，已选模板需要重新加载。取消或关闭不提交。
- 未选择模板时，不显示预览或错误。选择模板时，立即隐藏旧预览并呈现加载状态；只有当前弹窗、当前模板的最新成功响应才可以显示预览并允许创建。预览显示该响应的标题和说明。
- 仅当前请求失败时显示错误与重试入口。重试应请求当前模板，加载完成后可继续提交。旧成功和旧失败都不能覆盖现有状态，即使重开的弹窗又选了同一个模板。
- 名称去掉两端空白后不能为空；席位须为 1 到 20 的整数。模板模式下，在正确的模板加载完成前不能创建。不可提交时不得发送请求，改回有效状态后可正常提交。
- 创建成功后关闭弹窗并显示成功结果，包含已创建的项目名称。保留现有的键盘操作和表单可用性。无需改变 UI 风格、增加真实后端，或处理创建请求本身的并发写入。

## 本地接口和自动评分观察点

保留两个原生模式控件、原生模板下拉框、输入框及已有 `data-testid`。实现方式不限；评分器从页面操作和本地 HTTP 观察行为，不读取候选的内部状态或要求使用特定取消机制。

- `GET /api/templates/:id`：模板 ID 为 `studio` 或 `lab`；成功返回 `{id,title,description}`。评测会控制响应顺序，并注入失败或在重试时返回成功。
- `template-status` 的 `data-state` 为 `idle`、`loading`、`ready` 或 `error`。保留可见的加载／错误反馈及相应的预览、重试按钮。
- `POST /api/projects`：手动模式只发送 `{mode:"manual",name,seats}`，其中 `seats` 为数字；模板模式只发送 `{mode:"template",name,templateId}`。名称已去掉两端空白；不能带另一模式的字段。成功响应为 `{id,name,mode}`，用 `create-result` 显示成功结果。

不要改 grader、指纹或公开任务来绕过验证。按 [SETUP.md](SETUP.md) 在本地运行。
